# 需求文档：多地区节点出口

## 简介

AimiliVPN 当前仅支持单一 VPN 出口，即同一时刻只能选择一个地区（如日本或韩国），所有代理流量共用这一个出口。本需求旨在支持**同时有多个地区的出口**——例如同时拥有日本出口、韩国出口、香港出口，每个地区的出口节点独立工作：自动选取该地区最优节点、节点失效时自动切换。一台 VPS 即可同时提供多个地区代理出口。

## 术语表

- **地区出口 (Slot)**: 一个独立维护的 VPN 隧道槽位，绑定到指定的国家/地区。例如用户配置了 JP（日本）出口，系统自动在该国节点中选取最优的一个连接，失效自动切换。
- **出口槽位配置**: 用户通过 Web UI 指定「哪些地区各需要一个出口」。如用户设置 3 个槽位：日本、韩国、香港，则系统同时运行 3 个 OpenVPN 进程。
- **节点池 (Node Pool)**: 所有正在运行的地区出口的集合。

## 需求

### 需求 1: 多地区出口配置

**用户故事**: 作为 VPS 部署者，我希望一台 VPS 上同时跑多个地区的 VPN 出口，每个地区自动选取和更新该地区节点。

#### 验收标准

1. 系统 SHALL 支持用户通过 Web UI 配置出口地区列表，每个地区可以指定需多少个出口节点。
2. 每个出口地区 SHALL 拥有独立的 tun 网卡设备（tun0, tun1, tun2...）。
3. 每个出口地区 SHALL 独立从 VPNGate API 获取该国的可用节点列表。
4. 每个出口地区 SHALL 独立进行并发测速和连接测试。
5. WHEN 某地区节点失效时，该出口 SHALL 自动切换至同一地区的备用节点，不影响其他地区出口。

### 需求 2: 各地区逐立节点池状态管理

**用户故事**: 作为运维用户，我希望在管理后台上看到每个地区出口的实时状态。

#### 验收标准

1. 系统 SHALL 维护一个地区出口池，记录每个出口槽位的国家地区、连接状态、当前连接的节点 IP、延迟、出口 IP。
2. Web 管理界面 SHALL 通过调用 `/api/node_pool` 展示所有活跃地区出口的状态。
3. 系统 SHALL 保留现有单节点相关的所有 API 和状态变量，新增多地区节点池 API。
4. 前端界面 SHALL 新增"多地区出口"面板，显示每个地区出口的实时状态。

### 需求 3: 多地区节点即地区出口的自动精准维护

**用户故事**: 作为系统，我需要自动维护每个地区出口节点的健康，节点失效后自动切换。

#### 验收标准

1. 后台检在线程 SHALL 对每个地区出口独立进行出口连通性检测。
2. 测速守候 SHALL 对每个地区出口独立计算延迟。
3. 当某个地区出口健康检查失败时，系统 SHALL 仅将该出口标记为不可用，并发起该地区的节点切换，不中断其他地区出口。
4. 每个地区出口的自动更新节点切换逻辑 SHALL 复用现有的 `auto_switch_node` 机制。

### 需求 4: 向后兼容

**用户故事**: 作为现有用户，我不希望升级后功能损坏。

#### 验收标准

1. 如果只配置了 1 个地区出口，系统 SHALL 保持与现有版本一致的单节点行为。
2. 现有的 Web UI 所有功能和 API SHALL 保持不变。
3. 现有三种路由模式（智能自动/固定国家/固定 IP）SHALL 继续可用。
4. 多地区出口模式下，代理服务器 SHALL 保持与现有版本一致的调用接口。

| R4 | 向后兼容性 | 高 |
